# Повторитель действий в Chrome

`repeater_gui.py` — окно управления. `repeater.py` записывает действия пользователя на сайте и затем повторяет их в одном или нескольких **независимых экземплярах Chrome**. Записываются переходы, клики, ввод, выбор в списках, флажки, Enter/Escape и открытие вкладок. Для canvas используется клик по координатам. Элементы на обычных страницах находятся по CSS-селекторам, а Playwright ждёт их появления перед действием.

## Установка

Нужны Python 3.10+, установленный Google Chrome и Playwright:

```powershell
python -m pip install playwright
```

## Запуск через окно

Дважды нажмите `start_repeater.bat` или выполните:

```powershell
python repeater_gui.py
```

Укажите адрес сайта и нажмите **Начать запись**. Выполните действия в открывшемся Chrome. В поле **Текст успеха** введите текст, который виден только после успешного завершения цепочки, затем нажмите **Добавить проверку** и **Сохранить запись**. Укажите число браузеров и нажмите **Запустить повтор**. Результаты и скриншоты появятся в выбранной папке.

Во время CAPTCHA нажмите **Пауза / CAPTCHA**, пройдите её вручную, затем **Продолжить запись**. При повторении программа остановится на этом месте; после ручного прохождения нажмите **Продолжить после CAPTCHA**. Для каждого браузера проверка выполняется отдельно.

Поля с данными и прокси позволяют передать разные значения каждому браузеру. Их формат описан ниже.

## 1. Записать сценарий

```powershell
python repeater.py record "https://example.com" --output scenario.json
```

Откроется Chrome. Пройдите нужную цепочку вручную. В консоли введите `assert Текст успешного завершения`, затем `stop`, чтобы сохранить сценарий. Если встретилась CAPTCHA или проверка Cloudflare, введите `pause`, пройдите её в браузере, затем введите `resume`. При повторении на этом месте скрипт остановится и попросит пройти проверку вручную. Автоматического обхода защиты нет.

Пароли в JSON не сохраняются: вместо значения записывается имя переменной окружения. Например, для поля `#password` потребуется `REPEATER_SECRET_PASSWORD`. Перед повторением задайте её в среде запуска. Данные в других полях, включая логины, сохраняются как открытый текст; проверьте сценарий перед передачей кому-либо.

## 2. Повторить

```powershell
python repeater.py replay scenario.json --count 10
```

По умолчанию Chrome виден, чтобы можно было вручную пройти CAPTCHA. Для запуска без окон добавьте `--headless`; сценарий с ручной паузой требует видимый Chrome. Для каждого экземпляра создаётся отдельная сессия. Итоговые скриншоты и `report.json` сохраняются в `replay_output/`. При ошибке создаётся скриншот с суффиксом `_error.png`, а в отчёте указан номер неудавшегося шага. Скрипт завершается с ненулевым кодом, если хотя бы один браузер не дошёл до конца или не появился контрольный текст.

### Разные данные для браузеров

Отредактируйте `scenario.json`, заменив нужные значения полей на шаблоны, например `{{username}}` и `{{email}}`. Создайте `data.json` как массив объектов по числу браузеров:

```json
[
  {"username": "user01", "email": "user01@example.test"},
  {"username": "user02", "email": "user02@example.test"}
]
```

Запуск для двух браузеров:

```powershell
python repeater.py replay scenario.json --count 2 --data data.json
```

Для десяти браузеров добавьте в массив десять объектов и укажите `--count 10`. Путь к загружаемому файлу записывается как `{{file_path}}`; задайте его отдельно для каждого браузера через `data.json`.

### Прокси

Передайте JSON-массив параметров Playwright по одному объекту на браузер:

```json
[
  {"server": "http://proxy1.example:8080", "username": "user1", "password": "secret1"},
  {"server": "http://proxy2.example:8080", "username": "user2", "password": "secret2"}
]
```

```powershell
python repeater.py replay scenario.json --count 2 --proxies proxies.json
```

Файл с прокси содержит секреты открытым текстом: храните его локально и не отправляйте вместе со сценарием. Доступность конкретных прокси зависит от самих прокси и сайта.

## Проверка

```powershell
python test_repeater.py
python test_gui.py
```

Проверка записывает цепочку на локальной странице `demo_site.html`, затем воспроизводит её в десяти Chrome, проверяет реакцию на неверный результат, переход по ссылке и новую вкладку. Отдельно проверяются кнопки окна, запуск записи и повторения, ручная пауза. `demo_10_browsers.py` и `demo_output/` — материалы предыдущего демонстрационного прогона.

Для адаптации к конкретному сайту заказчика нужны его URL и маршрут действий. Сайты с закрытым shadow DOM, canvas, сложными виджетами или динамическими селекторами могут потребовать правки записанного сценария.
