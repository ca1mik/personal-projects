# Фасад Connect 0.1

Рабочая пилотная версия для одного фасадного предприятия. Содержит отдельную копию «Фасада», новый экран заказов, документ расчёта, журнал обмена и коннектор Битрикс24 через входящий вебхук.

## Посмотреть продукт

1. Полностью распакуйте архив в отдельную папку на Windows x64.
2. Запустите `start-demo.bat`.
3. Откроется http://127.0.0.1:3137/connect . Вход в демонстрацию автоматический.
4. Откройте любой из трёх вымышленных заказов и нажмите «Передать в CRM».
5. Перейдите в «Тестовую CRM» и проверьте сумму и XLSX в истории сделки. Повторная отправка сохраняет одну сделку и один документ для неизменённого расчёта.

Python и Node включены в поставку. Для локального показа отдельная установка зависимостей и доступ в интернет не требуются. Оставляйте окно запуска открытым; для остановки используйте `stop.bat`.

## Начать рабочий пилот

1. Остановите демонстрацию через `stop.bat`.
2. Запустите `start.bat`.
3. В браузере укажите название предприятия, логин владельца латиницей и пароль минимум из 12 символов.
4. Откройте «Подключение CRM». Выберите Битрикс24 и вставьте входящий вебхук своего портала с правами CRM.
5. Сохраните настройки и нажмите «Проверить сохранённое подключение». Проверка читает описание полей CRM и не создаёт сделки.
6. В «Рабочем месте» создайте заказ или импортируйте Excel-бланк. Сохраните заказ и вернитесь в Connect; нажмите «Обновить».
7. Проверьте состав и сумму, затем передайте заказ. Для существующей сделки можно указать её числовой ID. При такой привязке обновляется её сумма, а документ добавляется в историю.

В демонстрации и рабочем режиме используются разные базы: `runtime/demo` и `runtime/pilot`. В архиве нет рабочих баз, клиентских файлов, паролей и ключей портала из исходной установки. Данные для запуска создаются при первом старте на этом компьютере.

## Что уже работает

- Новый обзор, поиск заказов и фильтр по состоянию передачи в CRM.
- Расчёты, импорт Excel, документы, раскрой и производственные страницы из включённой версии «Фасада».
- Скачивание XLSX с составом и согласованной суммой заказа.
- Создание сделки Битрикс24 или привязка к существующей.
- Ручная отправка суммы, валюты и XLSX-документа со статусом заказа в историю сделки.
- Дополнительная запись статуса в существующее текстовое поле CRM и смена стадии по явному соответствию кодов.
- Восстановление связи по внешнему ID после потери ответа CRM, защита от повторной отправки неизменённого документа и журнал результатов.
- Зашифрованное хранение ключа вебхука, вход для владельца, резервная копия баз и файлов.

## Как устроена синхронизация

Данные передаются только после нажатия «Передать в CRM» или «Обновить в CRM». Фоновая автоматическая отправка в этой версии не выполняется.

При создании новой сделки сохраняются внешний ID заказа и уникальный источник этой установки. Перед повторным созданием проверяется наличие сделки с этими идентификаторами. Уже связанная сделка обновляется по её ID.

При неизменённом расчёте документ повторно не добавляется. Изменение состава, суммы или статуса создаёт новую версию документа. Статус всегда попадает в историю; переход CRM на другую стадию выполняется только при настроенном соответствии.

Если результат создания сделки или отправки документа неизвестен из-за сбоя сети, приложение сначала пытается подтвердить результат чтением CRM. Когда подтверждения нет, оно показывает сообщение и не выполняет слепое повторное создание. В таком случае проверьте портал и при необходимости укажите ID существующей сделки.

## Настройки Битрикс24

Поддерживаются облачные домены вида `company.bitrix24.ru`, `.com`, `.by`, `.kz`, `.eu` и `.de`. Коробочный Битрикс24 на произвольном домене в эту версию не входит.

Вебхук указывается целиком в виде `https://company.bitrix24.ru/rest/1/ключ/`. В интерфейсе сохранённый ключ больше не отображается. «Адрес вашего сервера» можно оставить пустым при локальном показе; для ссылок из CRM укажите доступный сотрудникам HTTPS адрес развёрнутой установки.

Необязательное поле статуса должно уже существовать в CRM, быть текстовым и иметь код `UF_CRM_...`. Пример соответствия стадий:

```json
{"new": "NEW"}
```

Используйте фактические коды своей воронки. Пустое соответствие сохраняет текущую стадию сделки. Движения денег в CRM, контакты и оплаченные счета автоматически не меняются.

## Данные и резервная копия

В «Подключении CRM» есть кнопка скачивания резервной копии. В архив входят база «Фасада», связи и журнал Connect, ключ шифрования настроек, конфигурация и загруженные файлы. Содержимое предназначено для восстановления вашей установки.

Восстановление сначала проверьте в отдельной копии продукта: остановите приложение, сохраните текущую папку runtime и поместите файлы копии в соответствующую папку `runtime/demo` или `runtime/pilot`. Не смешивайте режимы. Запустите приложение и проверьте заказ, документ и связь с CRM.

## Границы версии

- Версия предназначена для локального пилота одного предприятия. Сервер слушает только `127.0.0.1`; внешний доступ и HTTPS требуют отдельного развёртывания.
- Код коннектора проверен автоматическими тестами и локальной тестовой CRM. Проверка на реальном клиентском портале не проводилась: его ключ не предоставлен.
- Это отдельная интеграция через вебхук. OAuth-приложение Маркетплейса Битрикс24, модерация, биллинг подписки и amoCRM не реализованы.
- Передача текущей версии документов и статуса выполняется вручную. Источником суммы является «Фасад»; двустороннее редактирование расчёта не включено.
- Документ расчёта Connect — XLSX. Карты PDF формируются в производственных страницах «Фасада» и в эту отправку не прикладываются автоматически.
- Раскладка не гарантирует математически минимальный расход. Пригодность карт подтверждает технолог предприятия. Производственная себестоимость и управляющие программы станка не являются функциями Connect.
- Нагрузочную и производственную приёмку выполняйте на своём наборе заказов до рабочего запуска.

## Для разработчика

Новый код расположен в `connect/` и `launch.py`. Рабочая копия backend — `backend/app`. Исходные компоненты и скрипты поздних исправлений интерфейса сохранены в `source/frontend`; действующая сборка — `frontend/.next`.

Часть изменений исходного Portable была применена к собранному интерфейсу. Перед полной пересборкой необходимо перенести поздние исправления из `source/frontend/patches` в исходники и сверить поведение. Заменять текущую `.next` сборкой старого дерева без этой сверки нельзя.

При старте создаётся новая схема SQLite из текущих ORM-моделей и начальные справочники. Действующая база другого продукта сюда автоматически не переносится. Для обновлений после 0.1 требуется отдельный миграционный план.

Порты по умолчанию: 3137 — вход в продукт, 3138 — интерфейс производства, 8137 — API. Альтернативный набор: `python/python.exe launch.py --port 3157`. Папку данных можно перенести через переменную окружения `FASAD_RUNTIME_ROOT`. Журналы запуска находятся в `runtime/<режим>/logs`.

Тесты: `python/python.exe -m pytest connect/tests -q --basetemp <новая-папка-для-тестов>`. Результаты подготовки версии описаны в `VERIFICATION.md`.
