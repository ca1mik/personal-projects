# Контур — руководство по демоверсии

Система объединяет данные трёх участков: **заготовка**, **потребность сварки**, **документация**. Сотрудники работают с записями в приложении, директор видит проверенные показатели и причины проблем. После первоначального импорта Excel больше не нужен.

Начните с кнопки **«Как пользоваться →»** над выбором периода: в ней есть переходы к экранам и карта задания.

Это учебная демоверсия с вымышленными данными из задания. В базе сохранены 23 исходные строки и намеренные ошибки, чтобы можно было показать их обнаружение и исправление.

## 1. Как запустить

**Windows:** распакуйте архив в отдельную папку и откройте `Start.cmd`. Нужен Python 3.12 или новее. При первом запуске зависимости загружаются из PyPI, поэтому нужен интернет. Адрес: **http://127.0.0.1:8769**. Пока идёт показ, окно сервера должно оставаться открытым. Остановка — Ctrl+C.

Если порт 8769 уже занят работающей демоверсией, не запускайте второй экземпляр на том же порту.

Ручной запуск:

```powershell
py -3 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m uvicorn app:app --host 127.0.0.1 --port 8769
```

Для Linux/macOS используйте `python3` и `.venv/bin/python`. Excel и Codex для работы приложения не требуются.

**По внешней ссылке:** используйте выданные отдельно логин и пароль. Это отдельная копия данных; изменения в ней не меняют локальную базу владельца. Ссылка туннеля работает, пока включены компьютер, сервер и туннель. Учебные аккаунты в этой копии могут быть отключены. Для проверки рабочих ролей администратор может создать дополнительных пользователей в интерфейсе.

## 2. Вход и роли

В архивной локальной версии доступны учебные аккаунты. На странице входа кнопка роли заполняет поля; затем нажмите «Войти».

| Логин | Пароль | Что доступно |
|---|---|---|
| admin | demo-admin-2026 | Все данные, пользователи, роли, поручения |
| director | demo-director-2026 | Чтение всех данных, отчёты, назначение и проверка поручений |
| production | demo-production-2026 | Записи и отчёты заготовки, выполнение назначенных задач |
| welding | demo-welding-2026 | Записи и отчёты потребности сварки, выполнение назначенных задач |
| docs | demo-docs-2026 | Записи и отчёты документации, выполнение назначенных задач |

Директор не редактирует производственные записи, но может назначать задачи и проверять результат. Сотрудник видит весь свой участок, а не только строки с совпадающим именем. Статус назначенной задачи меняет ответственный; коллеги своего участка могут оставлять комментарии. Закрывает задачу директор или администратор.

Права проверяются сервером, включая отчёты, историю, задачи и объяснения изменений. Скрытие кнопок дополняет эти проверки. Роли встроенные: можно назначать одну из пяти ролей пользователю; конструктора произвольных новых ролей нет.

Учебные пароли предназначены только для вымышленных данных. Для реального использования смените пароли и отключите лишние аккаунты. Публичное производственное размещение с учебными доступами не настроено.

## 4. Главный рабочий сценарий

### Руководитель обнаружил проблему

1. Войдите как admin или director, выберите период **05–14.10.2026**.
2. В обзоре найдены пять проблемных строк заготовки. Факт по проверенным строкам — **290**, общий процент скрыт. Документация — **18 из 26**, или **69,2%**.
3. Откройте проблему **P-003 / LOT-03**: при плане 100 указан факт 1200. Это значение требует проверки, поэтому связанный дефицит неизвестен.
4. Нажмите «Создать задачу». Укажите понятное название, выберите ответственного production и будущий срок. Сохраните. Поручение появится в «Задачах и проблемах».

### Сотрудник проверил и исправил

5. Выйдите и войдите как production. На доске включено «Только назначенные мне». Откройте задачу и переведите её «В работу».
6. Через «Открыть источник» перейдите к записи. Для **учебного показа** примите допущение, что проверенный факт равен 120, и замените 1200 на 120. Приложение само не устанавливает правильное значение.
7. Ещё до сохранения предпросмотр покажет факт проверенных строк **290 → 410**. Сохраните. Сотрудник видит только свой участок; достоверный дефицит LOT-03 **10** появится у руководителя, имеющего доступ к обоим участкам.
8. Вернитесь к задаче. Оставьте комментарий о проверке и переведите её «На проверку».

### Руководитель принял результат

9. Войдите как director, откройте задачу на проверке. Посмотрите источник и показатели.
10. Укажите результат в комментарии и завершите задачу. Пустой результат при первом завершении не принимается.
11. Документация при исправлении заготовки останется **18 из 26**: связи между ними нет.
12. Под показателем нажмите «Почему менялись цифры?». Видны правка 1200 → 120, её автор, изменение проверенного факта на +120 и переход дефицита из неизвестного значения в 10.

**Статус задачи и качество данных — разные вещи.** Исправление записи не закрывает поручение автоматически. Закрытая задача также не исправляет запись. Если в источнике остались замечания, они продолжают отображаться в карточке и отчётах.

## 5. Как работают задачи

- Создаются руководителем из конкретной записи или карточки партии. Несвязанных с данными поручений в этом демо нет.
- Ответственным можно назначить активного пользователя с правом работы на нужном участке.
- Есть срок, описание, статус, комментарии и история действий. Просроченные открытые задачи отмечены.
- Ответственный может начать работу, передать результат на проверку и вернуть его в работу. Самостоятельно закрыть задачу сотрудник не может.
- Назначение, срок, описание и итоговую проверку меняют директор или администратор.
- Удалённый или ошибочный источник остаётся заметен; задача не маскирует проблему.
- Задачи не отсекаются периодом панели: поручение по записи за октябрь остаётся видно и при другом выбранном периоде.
- Версия карточки защищает от перезаписи более свежих изменений из другого окна.

## 6. Почему менялись показатели

Объяснение вычисляется по журналу реальных изменений записей. Для каждой правки система пересчитывает показатели выбранного периода до и после события по тем же правилам, что и основной отчёт.

Это важно для дублей: **удаление одной лишней строки может увеличить проверенный факт**, поскольку оставшаяся запись перестаёт считаться дублем. Простое вычитание удалённого значения дало бы неверный ответ.

Показываются до 20 значимых событий из последних 100 правок записей. Входы, назначения задач и комментарии в этот расчёт не входят. Права доступа сохраняются: сотрудник не получает объяснения по чужому участку. Старые события без автора так и подписаны. Для старых физически удалённых записей без доступных метаданных полное восстановление истории не обещается.

## 7. Отчёты, сводная и диаграммы

1. Откройте «Отчёты и сводная» и выберите период сверху.
2. Выберите участок и группировку. Для заготовки доступны сотрудник, партия, дата; для документации — сотрудник и дата; для сварки — партия и дата.
3. Нажмите «Записи» в строке группы, чтобы увидеть её состав.
4. Оранжевый столбец со звёздочкой — частичная сумма проверенных строк. Она не является достоверным итогом всей группы.
5. «Excel с диаграммами» скачивает XLSX с пятью листами: обзор, выбранная сводка, партии, первичные записи, диаграммы. Даты и проценты имеют форматы, колонки — ширины, таблицы — фильтры, ошибки выделены.
6. XLSX содержит рассчитанную сводку и нативные диаграммы Excel. Сводка не является объектом Excel PivotTable. Интерактивная смена группировки выполняется в приложении.
7. CSV оставлен для простого обмена данными; у него нет оформления Excel.

Руководитель получает общий обзор доступных участков и выбранную сводку. Выгрузка сотрудника ограничена его участком. Пример готового XLSX находится в `examples/report.xlsx`.

## 8. Правила расчётов и ошибок

- Заготовка: количества в единицах. Выполнение = сумма факта / сумма плана, а не среднее процентов.
- При ошибках из достоверных сумм исключается вся проблемная строка. Суммы помечены как частичные, общий процент скрыт; доля проверенных строк видна.
- Дубли номера записи ищутся внутри участка по всей базе, в том числе вне периода. До проверки исключены обе строки. Повтор партии при разных номерах сам по себе допустим.
- Количества должны быть целыми и неотрицательными. Пусто означает «неизвестно», ноль — подтверждённое отсутствие результата.
- Факт больше трёх планов требует проверки. Это явное допущение учебного демо, не универсальная производственная норма.
- Сварка связана с заготовкой по партии внутри выбранного периода. Дефицит = потребность − факт заготовки. «+» — дефицит, «−» — избыток. Нет одной стороны или есть ошибка — дефицит неизвестен, ноль не подставляется.
- Документация имеет собственные единицы — документы — и не зависит от выпуска заготовки.
- Нулевая сумма плана даёт неопределённый процент. Ошибочная дата выводится отдельно: достоверно включить такую запись в период нельзя.
- На дневных графиках крестик означает отсутствие достоверного значения, а не нулевой выпуск.

## 9. Где хранятся данные и как загрузить новые

Рабочая база — `data/operations.sqlite3`. Там находятся записи, исходные значения, пользователи, история, поручения и комментарии. После перезапуска всё сохраняется. Экспорт и страницы приложения не читают исходные Excel повторно.

Для резервной копии остановите сервер и скопируйте папку `data`. Для восстановления используйте её копию при остановленном сервере. Не удаляйте рабочую базу ради повторного импорта.

Для чистой учебной базы задайте другой путь:

```powershell
$env:OPERATIONS_DB = 'data/empty.sqlite3'
.venv\Scripts\python -m uvicorn app:app --host 127.0.0.1 --port 8769
```

Администратор увидит форму трёх XLSX. Нужен лист «Данные» с исходными заголовками. Все три файла импортируются одной транзакцией; ошибка одного отменяет импорт целиком. Повторный импорт в заполненную базу запрещён. Лист с примером формул не загружается: расчёты реализованы в приложении. Формулы внутри первичных значений не исполняются.

## 10. Как устроен код и что проверено

| Файл | Ответственность |
|---|---|
| app.py | API, база, запись изменений, первоначальный импорт |
| domain.py | Чтение XLSX, проверки, расчёты и связи участков |
| access.py | Пользователи, хеши паролей, сессии и серверные права |
| reporting.py | Группировки и генерация оформленного XLSX |
| workflow.py | Поручения, комментарии и объяснение изменений |
| static/app.js | Основные экраны и редактирование |
| static/features.js | История, админка, предпросмотр |
| static/workspace.js | Страницы отчётов, ролей и рабочая панель |
| static/flow.js | Доска задач и объяснения показателей |
| static/guide.js | Подсказки для ролей и сценарий проверки ТЗ |
| tests/ | Приёмочные проверки |

Стек: Python, FastAPI, SQLite, обычные HTML/CSS/JS. Графики интерфейса не требуют внешних CDN. XLSX формируется через openpyxl, без установленного Excel.

```powershell
.venv\Scripts\python -m pip install -r requirements-dev.txt
New-Item -ItemType Directory -Force test-results
.venv\Scripts\python -m pytest tests -q --basetemp test-results/new-run
```

Выбирайте новый пустой каталог `--basetemp`. **19 тестов** проверяют импорт и откат, работу после удаления временных исходников, сохранение после перезапуска, математику и независимость участков, права/CSRF, отчёты, историю, восстановление записей, цикл задачи, комментарии и пересчёт причин изменений. Исходные файлы владельца тестами не меняются.

Ограничения демо: нет SSO/MFA, почтового восстановления пароля, произвольного конструктора ролей, производственной инфраструктуры и интеграций с ERP/1С/Битрикс24. Пароли хранятся PBKDF2-хешами, сессия действует 8 часов; отключение пользователя или смена пароля завершает его сессии. Автообновление другого окна — примерно раз в 5 секунд. Бюджет и временной масштаб исходного задания не подразумевают полноценную ERP.
