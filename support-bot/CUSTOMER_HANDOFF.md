# Customer Handoff

## Что отправить заказчику

Передавать нужно весь проект целиком, корневой папкой или одним архивом `.zip`.

Обязательно включить:

- `src/`
- `migrations/`
- `prompts/`
- `content/`
- `legal/`
- `tests/`
- `.env.example`
- `docker-compose.yml`
- `Dockerfile`
- `docker-entrypoint.sh`
- `alembic.ini`
- `requirements.txt`
- `README.md`
- `DEPLOYMENT.md`
- `FINAL_AUDIT.md`

## Что не отправлять

Не включать в передачу локальные и временные артефакты:

- `__pycache__/`
- `.pytest_cache/`
- `.ruff_cache/`
- `.mypy_cache/`
- локальные `.db` файлы
- временные `.out` / `.err` логи
- личные токены и реальные ключи
- локальный `.env`, если он содержит ваши тестовые или боевые секреты

## В каком виде отправить

Рекомендуемый вариант:

1. Упаковать проект в `support-bot.zip`
2. Отдельно приложить краткое сопроводительное сообщение
3. В сообщении сослаться на:
   - `README.md`
   - `DEPLOYMENT.md`
   - `.env.example`

## Что должен получить заказчик

На стороне заказчика должно быть достаточно:

1. Распаковать архив
2. Скопировать `.env.example` в `.env`
3. Заполнить свои ключи
4. Выполнить:

```bash
docker compose up -d
```

При необходимости отдельно:

```bash
docker compose exec app alembic upgrade head
```

## Что попросить у заказчика подготовить

Для production запуска заказчику понадобятся:

- домен с HTTPS для webhook
- `TELEGRAM_BOT_TOKEN`
- при необходимости `TELEGRAM_PAYMENT_PROVIDER_TOKEN`
- `MAX_API_TOKEN` и при необходимости `MAX_WEBHOOK_SECRET`
- `YOOKASSA_SHOP_ID`
- `YOOKASSA_SECRET_KEY`
- `YOOKASSA_RETURN_URL`
- при необходимости `YOOKASSA_WEBHOOK_SECRET`
- ключи выбранного LLM провайдера
- `ADMIN_API_SECRET`
- `ADMIN_USER_IDS`
- support contact
- актуальные юридические реквизиты для оферты и privacy policy

## Что важно сообщить заказчику заранее

- Проект можно локально проверить и без ключей в demo/mock режиме.
- Для боевого запуска нужно заполнить `.env`.
- Реальные Telegram/MAX/YooKassa/LLM интеграции проверяются уже на ключах заказчика.
- Все основные сценарии и логика внутри проекта уже подготовлены.

## Готовый текст сопроводительного сообщения

Ниже текст, который можно почти без правок отправить заказчику.

---

Передаю готовый проект Telegram + MAX бота психологической поддержки.

В архиве находится полный исходный код, Docker-конфигурация, миграции, legal-документы, README и пошаговая инструкция по запуску.

Что нужно сделать с вашей стороны:

1. Распаковать проект
2. Скопировать `.env.example` в `.env`
3. Заполнить ваши ключи и реквизиты
4. Выполнить `docker compose up -d`

Если потребуется ручная проверка миграций:

`docker compose exec app alembic upgrade head`

Основные файлы для запуска и проверки:

- `README.md` — описание проекта и сценариев
- `DEPLOYMENT.md` — пошаговый запуск
- `.env.example` — список всех переменных

В проекте реализованы:

- Telegram
- MAX
- онбординг
- 18+
- обязательные согласия
- бесплатное превью на 3 ответа
- тарифы и подписки
- интеграция с YooKassa
- LLM-слой
- кризисный протокол
- admin endpoints и аудит
- ежедневные check-in и weekly summary

Локально проект можно проверить и без ключей в demo/mock режиме. Для production работы нужно подставить ваши реальные ключи и проверить внешние webhook и платежи.

---

## Минимальный чек-лист при передаче

- проверить, что в архиве есть `README.md`, `DEPLOYMENT.md`, `.env.example`
- проверить, что в архив не попал локальный `.env`
- проверить, что в архив не попали временные `.db` и кэши
- при необходимости отдельно прислать заказчику список переменных, которые он должен заполнить в первую очередь

## Переменные, которые заказчику лучше заполнить в первую очередь

- `APP_ENV`
- `DATABASE_URL`
- `REDIS_URL`
- `WEBHOOK_BASE_URL`
- `TELEGRAM_BOT_TOKEN`
- `MAX_API_TOKEN`
- `YOOKASSA_SHOP_ID`
- `YOOKASSA_SECRET_KEY`
- `YOOKASSA_RETURN_URL`
- `LLM_PROVIDER`
- ключи выбранного LLM
- `ADMIN_API_SECRET`

## Если хочешь передавать “под ключ”

Перед отправкой заказчику можно сделать финальную упаковку так:

1. Удалить локальные кэши и временные файлы
2. Проверить, что нет локального `.env`
3. Упаковать корень проекта в `.zip`
4. Отправить архив + короткое сопроводительное сообщение из этого файла
