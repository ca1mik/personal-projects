# Автоматическая глубина для Telegram

Бот выбирает глубину без ручного переключения модели. Короткие приветствия, шутки и небольшой список бытовых команд получают `low`. Распознанные важные поручения, работа с кодом, отправка писем, деньги и системные изменения получают `high`. Остальные и непонятные запросы — `medium`. Это консервативные правила, а не безошибочное понимание важности.

Используется установленный официальный MCP `codex-app-tools`, инструмент `send_message_to_thread` с параметром `thinking`; параметр `model` не передаётся. Клиент обнаруживает текущий канал приложения заново, в том числе после перезапуска. Перед отправкой нативным `read_thread` проверяется завершение активного поручения. Отправки сериализованы.

Настройка: `assistant_auto_reasoning: true` в `config.json`. Выбор записывается в событие `reasoning_selected` и в `bridge_queue:<task_id>`. Если канал недоступен до вызова отправки, используется прежняя CLI-очередь с однократным уведомлением о недоступности автовыбора. После начала вызова отправки автоматического повтора нет: неопределённый исход требует проверки, чтобы поручение не выполнилось дважды.

Подтверждение живой проверки: `artifacts/auto-reasoning-live-20261024.json`. Проверка выполнена без переменных окружения Codex: параметры `low` и `medium` действительно отразились в метаданных того же чата, модель сохранилась. Точное ускорение полного ответа зависит от задачи, очереди и инструментов; время передачи не равно времени выполнения.
