# Подтверждение доставки · 27.10.2026

Новые финальные ответы связанного чата атомарно связываются с сообщениями очереди через task_outbox. Состояние выполнения задачи и состояние доставки независимы. `/progress`, `/tasks`, `/history` показывают число подтверждённых отправок и ожидание/повтор после ошибки.

После успешного ответа Telegram сохраняются outbox.sent, sent_at и receipt. Метаданные кнопок оценки обновляются после этой записи: их ошибка не возвращает уже доставленное видео в очередь. Для редакционных публикаций отметка времени слота сохраняется вместе с квитанцией. Ошибка отправки сохраняется в last_error с очисткой секретов; повтор использует прежнюю очередь и задержку.

Квитанция подтверждает принятие API Telegram, а не прочтение владельцем. После неопределённого сетевого сбоя или падения между ответом Telegram и записью SQLite повтор всё ещё возможен: Bot API не предоставляет ключ идемпотентности. Старые записи sent=1 без квитанций не пересылаются и не получают вымышленные отметки времени.

Локальные команды направляют подходящие MP4/M4V через sendVideo. Определение метода использует существующие проверки заголовка MP4 и лимита 49 МиБ. Полноценная проверка дорожек ffprobe перед отбором материала остаётся обязанностью ассистента.

Проверено: 183 теста, включая сохранение связей после открытия базы заново, переход очередь → ошибка → подтверждение, маршрутизацию MP4 и отсутствие повторной отправки при сбое кнопок оценки. Сетевые вызовы в тестах подменены; реальные пользовательские ролики тестами не отправлялись.
