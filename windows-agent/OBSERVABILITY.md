# Telegram и этот чат Codex

Обновлено 24 октября 2026. Обычный текст, голос после локального распознавания, `/ask ТЕКСТ` и `/goal ТЕКСТ` направляются в чат **«Создать автономного AI-агента для ПК»**. Для прежнего изолированного исполнителя есть явная команда `/local ТЕКСТ`.

Бот использует официальный `codex queue --thread … --message …`. Подтверждение очереди означает доставку в очередь, а не завершение поручения. Если чат занят, поручение ждёт обработки. Приложение Codex должно оставаться открытым; выключенный ПК не принимает сообщения.

Обратный канал читает публичные ответы через App Server `thread/turns/list`. В Telegram появляется одна обновляемая карточка текущего хода работы, затем полный итоговый ответ. Обновление карточки — не чаще раза в 15 секунд; проверка новых записей — примерно раз в 3 секунды. Чтение не запускает отдельную модель и не возобновляет чат в другом процессе.

Пересылаются только публичные сообщения помощника `commentary` и `final_answer` из связанного чата. Внутренние рассуждения, сырой вывод инструментов и другие чаты не пересылаются. При первом подключении старая история не воспроизводится. Разрешённые файлы из итогового ответа в outputs доставляются вложениями; рабочие базы, журналы, секреты и виртуальное окружение исключены.

| Команда | Что показывает |
|---|---|
| `/sync` | Связанный чат, свежесть чтения ответов, число ожидающих поручений |
| `/ping` | Проверку входящего сообщения и ответа Telegram |
| `/progress 15` | Состояние конкретной задачи, последний наблюдаемый этап и итог |
| `/status` | Общую очередь, состояние сервиса, нагрузку ПК |
| `/logs 15` | Краткие события задачи |
| `/selftest` | Автоматические проверки обработчиков и соединения с Bot API |

`queued_in_codex` означает ожидание; `in_codex` — получено публичное сообщение по поручению; `completed` — прочитан итоговый ответ. Проценты готовности не выдумываются. Для `/local` этапы берутся из потока `codex exec --json`, уведомления ограничены одним за 120 секунд; детали доступны через `/progress`.

`/stop` ставит приём новых поручений на паузу и останавливает локальные задачи. Уже переданное в Codex поручение останавливается кнопкой **Stop в приложении Codex**. `/cancel` не выдаёт такое поручение за отменённое. После неоднозначного сбоя постановки в очередь автоматический повтор запрещён: сначала надо проверить результат.

Проверки: **67 тестов прошли**. Реальные сообщения `/ping`, `/selftest`, `/ask` и `/sync` приняты из Telegram. Самодиагностика №14 выполнилась и отправила отчёт. Поручение №15 выполнено в этом чате: итог TG_LINK_OK сохранён, ответ доставлен в Telegram (запись отправки №138). Обратная передача публичных обновлений подтверждена реальными отправками и редактированием Telegram-карточки. Полный цикл Telegram → этот чат → Telegram подтверждён.

Источники интерфейсов: [Codex queue](https://learn.chatgpt.com/docs/developer-commands), [App Server](https://learn.chatgpt.com/docs/app-server), [Codex exec](https://learn.chatgpt.com/docs/non-interactive-mode).


## Устойчивость синхронизации — дополнение 24 октября

- Ответы догружаются страницами до сохранённой границы. Простой сервиса, за который появилось больше пяти ходов, больше не ограничивает чтение последними пятью. Реальная проверка прочитала 7 ходов и нашла границу; файл результата — artifacts/bridge-recovery-check.json.
- Изменение текста публичного сообщения с тем же ID обновляет существующую карточку прогресса с сохранением ограничения частоты. Старая история при миграции не пересылается повторно.
- Итоговый ответ, завершение соответствующей задачи и постановка ответа/файлов в локальную очередь доставки записываются одной транзакцией SQLite. Проверен отказ записи, откат и успешное повторение без второй записи отправки. Telegram сам не предоставляет этой реализации ключ идемпотентности для sendMessage: при потере ответа сети после принятой отправки повтор всё ещё возможен; это не обещание строгого exactly-once на стороне Telegram.
- При первом подключении известная ожидающая задача обрабатывается, даже если остальная старая история пропускается.

Финальная проверка: 67 тестов прошли. Тест №15 с TG_LINK_OK завершён и доставлен обратно в Telegram. Новое поручение №16 также получено из Telegram и выполняется в этом чате.
