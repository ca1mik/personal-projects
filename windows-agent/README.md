До входа в Windows интерактивный автозапуск не срабатывает; удалённое включение ПК не настроено. Подробная инструкция: [STARTUP-AND-CONTROLS.md](STARTUP-AND-CONTROLS.md).

Сервис установлен и запущен на этом ПК. Бот: [@MyClawHelperComputeBot](https://t.me/MyClawHelperComputeBot). Доступ привязан к одному Telegram-аккаунту через одноразовый код. Токен хранится в Windows DPAPI и не включается в исходный архив.

Пишите обычным языком или присылайте голосовое на русском. Поручения поступают в этот чат Codex «Создать автономного AI-агента для ПК», ход работы и итог возвращаются в Telegram. Приложение Codex должно оставаться открытым; занятой чат обрабатывает очередь после текущей работы. Например:

- «Создай консольный список дел, протестируй и пришли архив».
- «Что ты делал в прошлой задаче?»
- «Завтра в 9 утра напомни проверить отклики».
- «Найди вакансии технической поддержки в Нижнем Новгороде» — после подключения доступа hh.ru.

Голос распознаётся локально faster-whisper/base на CPU, до пяти минут на сообщение. Возможны ошибки распознавания. При неясном поручении уточняйте его текстом; критические действия требуют отдельного согласия. Аудио не отправляется в сервис распознавания, но текст поручения и нужные для работы материалы передаются модели Codex. История и входящие файлы сохраняются локально.

## Управление

В папке установки выполните в PowerShell:

```powershell
.\Start-Agent.ps1
.\Stop-Agent.ps1
.\.venv\Scripts\python.exe -X utf8 manage.py status
.\.venv\Scripts\python.exe -X utf8 manage.py backup
```

В Telegram:

| Команда | Действие |
|---|---|
| `/ping`, `/sync` | Проверка связи и состояния связанного чата |
| `/ask текст`, `/goal текст` | Поручение / цель в этот чат Codex |
| `/local текст` | Отдельная локальная задача |
| `/selftest` | Диагностика команд и Bot API |
| `/status` | Состояние ПК и очереди |
| `/tasks`, `/history` | Короткие номера и состояния задач |
| `/progress`, `/progress 3` | Последний наблюдаемый этап Codex и результат выбранной задачи |
| `/cancel 3` | Отмена локальной задачи №3; переданную работу останавливайте в Codex |
| `/retry 3` | Продолжение после исправимой ошибки |
| `/logs 3` | Краткий журнал задачи |
| `/screenshot`, `/windows` | Снимок рабочего стола / список окон |
| `/hh запрос`, `/hhstats` | Поиск вакансий / статистика истории |
| `/every 60 поручение` | Повтор раз в час |
| `/schedules`, `/unschedule ID` | Просмотр / отключение расписаний |
| `/approve 3 КОД`, `/deny 3` | Одно согласие на показанный шаг / отказ |
| `/stop` | Пауза новых поручений и отмена локальных задач |
| `/resume` | Снять паузу |
| `/shutdown`, `/reboot`, `/cancelshutdown` | Выключить / перезагрузить ПК через 60 сек / отменить |
| `/service_stop` | Завершить только сервис до локального запуска |
| `/help` | Справка |

Согласие связано с хешем конкретного действия, выдано только владельцем и действует 15 минут. Изменённый план и истёкший код не исполняются. Повтор внешнего действия после неопределённого исхода требует сначала проверить его результат.

## Автозапуск и восстановление

Задание планировщика Windows `PersonalWindowsAgent` зарегистрировано при входе текущего пользователя, с уровнем `Limited`. Оно запускает скрытый supervisor. Администраторские права постоянно не используются. Для создания задания на другом ПК: `Install-Autostart.ps1`; при отказе планировщика предусмотрен ярлык в папке автозагрузки.

Supervisor перезапускает упавший процесс с задержкой до 60 секунд и проверяет heartbeat. SQLite хранит очередь и промежуточные результаты. Безопасные прерванные шаги возвращаются в очередь. Незавершённые внешние действия помечаются для проверки, чтобы не повторять отправки/нажатия вслепую. Максимум — 12 шагов в одном поручении, отдельная разработка ограничена 30 минутами. При длинном проекте прогресс сохраняется в его папке.

Если сервис не отвечает: запустите `manage.py status`, проверьте `logs/service.log`, затем `Stop-Agent.ps1`, `Start-Agent.ps1` и `/resume`. Если не работает только Codex — `codex login status`; при необходимости выполните `codex login` локально. При восстановлении базы сначала остановите агент и сохраните копии `agent.sqlite3`, `agent.sqlite3-wal`, `agent.sqlite3-shm`, затем восстановите нужную копию из `backups`. Не заменяйте базу работающего процесса.

Для аварийной остановки без Telegram: `Stop-Agent.ps1` или создайте файл `STOP` в этой папке. `/stop` в Telegram оставляет бот доступным для `/resume`; уже переданную в связанный чат работу останавливайте кнопкой Stop в Codex. `/service_stop` завершает только сервис; `/shutdown` теперь выключает компьютер. Распознавание речи и Codex запускаются отдельными процессами и завершаются при отмене задачи. Крайний левый верхний угол экрана включает встроенный failsafe PyAutoGUI при следующем GUI-действии.

Сервис работает только при включённом ПК и доступной сети. Запуск при входе не означает работу до входа в Windows. Управление GUI требует открытого интерактивного сеанса и может занять мышь/клавиатуру; оно не гарантирует незаметную работу параллельно с человеком. Спящий или заблокированный ПК не подходит для GUI-задач.

## Codex и инструменты

По умолчанию используется связанный чат и его разрешения Codex. Описанные ниже локальный планировщик, профиль MXC и подтверждения шагов относятся к явному режиму `/local`. Этот режим использует установленный Codex CLI с текущей авторизацией ChatGPT. Отдельный API-ключ для текста не требуется; действует квота вашего Codex. Общие пользовательские MCP/плагины в запуски агента не подхватываются. Для планирования применяется чтение; для разработки — профиль MXC с записью в текущий проект, необходимыми путями Python/Node/Git/PowerShell и ограниченным набором доменов пакетных реестров. Оболочка хоста не получает внутренние API-ключи и каналы текущего приложения.

Произвольный PowerShell вне проекта, изменение чужих окон, HR-ответы, запись подтверждённых фактов и расширения требуют одного согласия на конкретный показанный шаг. Код модели и инструкции — дополнительные меры, а не доказательство полной защиты от prompt injection. Профиль Codex ограничивает локальные команды; отдельно одобренный PowerShell/GUI работает с правами вашего пользователя. Не одобряйте непросмотренные скрипты и неизвестные расширения.

Браузерный адаптер использует установленный Edge через Playwright в отдельном чистом контексте. Он читает страницы и делает снимки; сохранённая авторизация вашего обычного браузера не используется, отправка форм этим адаптером не реализована. Остальные сценарии выполняются через отдельные инструменты с согласованием.

Скриншот рабочего стола отправляется владельцу и может содержать личные сведения. Не запрашивайте его при открытых паролях и секретах.

## hh.ru

Поиск: Нижний Новгород, зарплата в рублях от 80 000, приоритет подтверждённому офисному формату; по умолчанию IT, CRM, автоматизация, техподдержка. Верхняя граница вилки 80 000 не выдаётся за гарантированную нижнюю границу. Учитываются валюта, формат, gross/net; формат без данных помечается для уточнения. Сохраняются ID и возможные повторные публикации по работодателю/названию/региону. Один поиск получает до 30 свежих вакансий; проверка полной карточки и соответствия опыту нужна перед откликом.

Реальный анонимный запрос на этом ПК вернул **HTTP 403**. Обход CAPTCHA или иных ограничений не выполняется. Без OAuth живой поиск пока не подтверждён.

Для разрешённого доступа:

1. Зарегистрируйте своё приложение на [dev.hh.ru](https://dev.hh.ru/) и получите доступ. Редирект должен соответствовать настройке приложения, по умолчанию `http://127.0.0.1:8767/callback`.
2. На этом ПК запустите `.\.venv\Scripts\python.exe -X utf8 manage.py hh-login`.
3. Введите client ID и скрытый client secret локально. Авторизацию в официальном окне hh.ru выполните самостоятельно. Пароль hh.ru агент не получает.
4. Токены сохранятся через DPAPI. Предусмотрено обновление access token по refresh token.

Подключены методы чтения истории и чатов, подготовка правдивых ответов и отправка сообщений через `/common/chats/{chat_id}/messages` с отдельным согласованием и ключом идемпотентности. Они не проверены на вашем аккаунте без OAuth. Сообщения помечаются как автоматические. Автоматическое прохождение анкет и HR-ботов не реализовано: доступ и правила конкретной анкеты неизвестны, неизвестные ответы передаются пользователю.

Автоотклики **отключены**: официальная документация ссылается на `apply-to-vacancy`, но его описания нет в полученной public OpenAPI. Нельзя подтвердить доступ и способ отправки без приложения/OAuth. Доступный сейчас сценарий — подобрать вакансии, подготовить резюме/письмо и ссылку для ручного отклика. Не считайте отсутствие метода в скачанной схеме доказательством полного отсутствия возможности в hh.ru.

Для исходного резюме пришлите TXT, DOCX или PDF с текстовым слоем и подписью, что это ваше резюме. Модуль сохраняет оригинал, извлекает факты только с дословными цитатами и создаёт три консервативные версии. Это перестановка подтверждённого содержания, а не выдумывание нового опыта. OCR для сканов не установлен. Обработка вашего реального резюме пока не проверена, поскольку оно не предоставлено.

Историю можно импортировать локально:

```powershell
.\.venv\Scripts\python.exe -X utf8 manage.py hh-import C:\path\history.json
```

JSON — список объектов или `{ "items": [...] }`; CSV — UTF-8 с полями `vacancy_id,status,resume_id`. Статистика различает неизвестные просмотры и нулевые просмотры. Автоматический характер/причина отказа без доказательств не утверждаются. Сравнение резюме по доступной истории возможно, но причинное влияние версии резюме статистика не доказывает.

При привязке созданы два расписания: проверка новых вакансий раз в 6 часов и статистика ежедневно в 19:00 МСК. Повторяющаяся ошибка доступа не спамит уведомлениями; проверка при 403/429 отключается до авторизации. Пропущенные интервалы не создают лавину задач после выключения ПК.

## Секреты и обновления

Переданный в переписке токен рекомендуется перевыпустить через BotFather. Новый токен вводится **только локально**: `Set-TelegramToken.ps1`, затем перезапуск сервиса и `/resume`. В чат токен отправлять не нужно. Подменять владельца на первый случайный `/start` бот не позволяет.

При переносе на другой ПК используйте `Install.ps1`, отдельно установите/авторизуйте Codex и настройте секреты. Версии зависимостей зафиксированы в `requirements.txt` и полном `requirements.lock.txt`; PyAV закреплён на 16.1.0 из-за несовместимости faster-whisper с установленной ранее 19.0.2.

Расширения добавляются без изменения ядра: локальный файл в `extensions/`, асинхронные обработчики в `TOOLS`, затем явное включение в `config.json` как `{"extensions":[{"file":"my_tool.py","sha256":"проверенный SHA256"}]}`. Имена инструментов начинаются с `ext_`; описание инструмента передаётся планировщику. Любое изменение файла требует обновить проверенный хеш. Загрузка из интернета и автоматическая установка расширений не включены. Любое действие расширения требует согласия.

## Проверки

### Как наблюдать за работой

Основной маршрут синхронизирован с этим чатом: текст и голос передаются штатной очередью Codex, публичный ход работы отображается одной редактируемой карточкой, итог приходит отдельным ответом. `/sync` показывает связь, `/progress НОМЕР` — задачу. Если текущая работа ещё идёт, новое поручение ждёт в очереди. `/stop` и `/cancel` не останавливают уже переданное в Codex исполнение: для него нужна кнопка Stop в приложении.

Для `/local` используется отдельный поток `codex exec --json`, ограничение частоты уведомлений и постоянный журнал. Сырые команды, их аргументы, вывод программ и внутренние рассуждения в сообщения прогресса не пересылаются. Проценты готовности не выдумываются.

См. [INSTALLATION-REPORT.md](INSTALLATION-REPORT.md). Установку нельзя считать выполненной на все 100%: для hh.ru нужны ваш OAuth-доступ и резюме; для проверки нажатий/ввода GUI нужна отдельная завершённая проверка. Система является работающей локальной реализацией с описанными пределами, а не обещанием неограниченного управления всеми программами.

## Личная лента, почта и напоминания — 24 октября

Настроено расписание Codex «Личная лента в Telegram»: каждый час с 09:30 до 21:30 МСК. Утром — новости и важная почта; днём — идея стартапа и шутка; в 17:30 — мем или милая картинка; вечером — полезное новое и ближайшие напоминания. Новые темы задаются `/topics ТЕМЫ`, лента выключается `/feed off`, включается `/feed on`, состояние — `/feed status`. `/feed` без аргумента готовит разовую подборку.

Почта читается через подключённый Gmail этого чата, без копирования OAuth-секретов в сервис. Письма не отправляются и не меняются. `/mail` готовит обзор писем, требующих действия, с датами и ссылками; одинаковые сбои доставки объединяются. Для фактов используются веб-проверка и первоисточники. Отсутствие свежих новостей не маскируется старыми. Картинки создаются встроенным Imagegen; нужен доступ к инструменту и квота, иначе бот честно отвечает текстом. Подходящие PNG/JPEG/WebP отправляются как фото, прочие файлы — документами.

| Команда | Действие |
|---|---|
| `/news [тема]` | Свежие проверенные новости со ссылками |
| `/joke`, `/meme`, `/cute` | Шутка, добрый мем, милая картинка |
| `/idea [пожелание]` | Идея с MVP, аналогами и проверкой спроса |
| `/mail`, `/plan` | Важная почта, план дня по известным фактам |
| `/remind 20м размяться` | Напоминание через 20 минут |
| `/remind завтра 10:00 позвонить` | Напоминание на конкретное время МСК |
| `/remind 2026-10-26 14:00 встреча` | Напоминание с датой |

Фраза «Напомни через 20 минут размяться» принимается текстом и после распознавания голосового. Такой таймер не ждёт модели: служба отправляет уведомление непосредственно из сохранённого расписания. При выключенном/спящем ПК сработает после возобновления работы; для более точной доставки ПК должен оставаться включённым. `/stop` ставит сервис на паузу вместе с таймерами; `/resume` продолжает работу. Ночная пауза личной ленты не отменяет явно выбранное время напоминания.
